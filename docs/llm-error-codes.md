# 拾忆 LLM 错误代码说明

拾忆会保留模型服务返回的 HTTP 状态码、`error.code`、`error.type`、`error.param` 和 `error.message`。
聊天状态栏显示完整的可行动说明，运行审计日志还会记录结构化错误字段。

| HTTP | 含义 | 拾忆处理 |
| --- | --- | --- |
| 400 | 请求参数错误 | 不走通用网络重试；根据字段尝试一次兼容降级，例如移除不支持的参数。仍失败则保留错误并结束本轮。 |
| 401 | 身份验证失败 | 检查 API Key、认证头和配置的服务地址。 |
| 403 | 没有调用权限 | 检查账号权限、模型权限、组织或网关策略。 |
| 404 | 接口或模型不存在 | 检查协议、路径、模型 ID 和网关前缀。 |
| 408 | 请求超时 | 可自动重试一次。 |
| 409 | 请求冲突 | 可自动重试一次，重点检查会话或请求状态。 |
| 413 | 请求内容过大 | 检查上下文、图片和工具输出，优先压缩或缩短内容。 |
| 422 | 请求语义不合法 | 检查字段组合、工具参数和模型能力；通常不盲目重试。 |
| 429 | 请求过于频繁或额度不足 | 自动重试一次；仍失败时检查限流和余额。 |
| 500 | 模型服务端异常 | 自动重试一次。 |
| 502 | 网关转发异常 | 自动重试一次，并检查代理、网关和上游状态。 |
| 503 | 服务暂不可用 | 自动重试一次。 |
| 504 | 网关超时 | 自动重试一次。 |

## 流式中断

流式响应没有正常结束标志、连接提前断开或长时间无数据时，归类为“回复中断”，不伪装成 HTTP 400。
拾忆会显示“回复中断，正在自动重试（1/1）…”。第二次仍失败时显示“回复中断，自动重试失败：原因”，并保留已经收到的内容和审计日志。

## 400 常见字段

- `error.code`：供应商的机器可读错误码。
- `error.type`：供应商的错误类型，例如 `invalid_request_error`。
- `error.param`：触发错误的请求字段，例如 `reasoning_effort`、`max_tokens` 或 `image_url`。
- `error.message`：供应商返回的具体原因，排查时优先查看这一项。
